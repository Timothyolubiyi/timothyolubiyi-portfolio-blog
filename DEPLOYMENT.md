# Deployment Guide — Timothy Olubiyi Portfolio

This guide walks through deploying the React portfolio to AWS using S3 + CloudFront using the Terraform configuration generated by `/scaffold-terraform`.

## Architecture

```
React (Vite) → npm run build → dist/
           ↓
        S3 Bucket (private)
           ↓
    CloudFront Distribution
           ↓
   ACM SSL Certificate
           ↓
  timothyolubiyi.name.ng
```

**No EC2. No Nginx. Fully serverless.**

---

## Prerequisites

- [ ] AWS account with appropriate permissions
- [ ] AWS CLI configured: `aws configure --profile timothy-portfolio`
- [ ] Terraform >= 1.0: `terraform version`
- [ ] Node.js 18+: `node --version`
- [ ] Domain registered and DNS provider accessible (for Route 53)
- [ ] Git installed and repo initialized

---

## Step 1: Prepare Terraform Configuration

```bash
cd terraform/

# Copy example variables file
cp terraform.tfvars.example terraform.tfvars

# Edit with your values
nano terraform.tfvars
```

**Update `terraform.tfvars`:**
- `domain_name`: Your domain (e.g., `timothyolubiyi.name.ng`)
- `aws_region`: Your preferred AWS region
- `aws_profile`: Your AWS CLI profile name

Leave `certificate_arn` empty to create a new certificate automatically.

---

## Step 2: Validate Terraform

```bash
# Check formatting
terraform fmt -check

# Validate configuration
terraform validate

# Show planned changes
terraform plan -out=tfplan
```

**Review the plan output carefully.** It should show:
- S3 bucket creation
- CloudFront distribution creation
- ACM certificate creation (if `certificate_arn` is empty)
- Route 53 records for domain validation
- IAM role for GitHub Actions

---

## Step 3: Build React Application

```bash
cd ..  # Back to project root

# Install dependencies
npm install

# Build for production
npm run build

# Verify build output
ls -la dist/
```

**Build should succeed with no errors.** Check that `dist/` contains:
- `index.html`
- `assets/` folder with JS/CSS files

## Step 4: Human Approval

**⚠️ STOP HERE BEFORE PROCEEDING**

Review the Terraform plan output. Ensure you are ready to:
1. Create S3 bucket
2. Create CloudFront distribution
3. Create ACM certificate and validate via DNS
4. Create Route 53 records

This will incur AWS charges (~$1-5/month for typical usage).

---

## Step 5: Deploy Infrastructure

```bash
cd terraform/

# Apply the Terraform plan (REQUIRES YOUR APPROVAL)
terraform apply tfplan

# Wait for completion (5-10 minutes)
# Watch for certificate validation in AWS console
```

**Important:** If using a new ACM certificate, you must validate it via DNS:

1. Go to AWS Certificate Manager console
2. Find the pending certificate for your domain
3. Click "Create records in Route 53" (automatically creates CNAME records)
4. Wait for validation (typically 5 minutes)

You can also manually create the CNAME records shown in the Terraform output:

```bash
terraform output certificate_validation_records
```

## Step 7: Upload React Build to S3

```bash
# Navigate to project root
cd ..

# Get bucket name from Terraform output
BUCKET_NAME=$(cd terraform && terraform output -raw s3_bucket_name)

# Sync build artifacts to S3
aws s3 sync dist/ s3://${BUCKET_NAME} --delete --region us-east-1

# Verify upload
aws s3 ls s3://${BUCKET_NAME}
```

**Expected output:** Files from `dist/` uploaded to S3 bucket.

---

## Step 8: Invalidate CloudFront Cache

```bash
# Get distribution ID from Terraform output
DISTRIBUTION_ID=$(cd terraform && terraform output -raw cloudfront_distribution_id)

# Invalidate all files (forces refresh)
aws cloudfront create-invalidation \
  --distribution-id ${DISTRIBUTION_ID} \
  --paths "/*" \
  --region us-east-1

# Verify invalidation
aws cloudfront list-invalidations \
  --distribution-id ${DISTRIBUTION_ID} \
  --region us-east-1
```

**Expected:** Invalidation in "InProgress" state, then completes within 1-2 minutes.

## Step 10: Set Up GitHub Actions CI/CD (Optional)

Create `.github/workflows/deploy.yml`:

```yaml
name: Deploy Portfolio

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    
    permissions:
      id-token: write
      contents: read
    
    steps:
      - uses: actions/checkout@v3
      
      - uses: actions/setup-node@v3
        with:
          node-version: '18'
      
      - run: npm install && npm run build
      
      - uses: aws-actions/configure-aws-credentials@v2
        with:
          role-to-assume: arn:aws:iam::${{ secrets.AWS_ACCOUNT_ID }}:role/timothy-portfolio-github-actions-role
          aws-region: us-east-1
      
      - run: |
          aws s3 sync dist/ s3://${{ secrets.S3_BUCKET_NAME }} --delete
          aws cloudfront create-invalidation \
            --distribution-id ${{ secrets.CLOUDFRONT_DISTRIBUTION_ID }} \
            --paths "/*"
```

### Set GitHub Secrets

Go to GitHub repository settings → Secrets and variables → Actions → New repository secret:

- `AWS_ACCOUNT_ID`: Your AWS account ID
- `S3_BUCKET_NAME`: From `terraform output s3_bucket_name`
- `CLOUDFRONT_DISTRIBUTION_ID`: From `terraform output cloudfront_distribution_id`

## Troubleshooting

### Certificate Validation Fails

```bash
# Check certificate status
aws acm describe-certificate \
  --certificate-arn $(cd terraform && terraform output -raw acm_certificate_arn) \
  --region us-east-1

# Manually create Route 53 records if needed
# Check CNAME record from AWS Certificate Manager console
```

### CloudFront Returns 403 Forbidden

```bash
# Check S3 bucket policy
aws s3api get-bucket-policy --bucket $(cd terraform && terraform output -raw s3_bucket_name)

# Verify OAC is configured
# Re-run: terraform apply
```

### Website Shows Old Content

```bash
# Force CloudFront cache invalidation
aws cloudfront create-invalidation \
  --distribution-id $(cd terraform && terraform output -raw cloudfront_distribution_id) \
  --paths "/*"

# Clear browser cache (Ctrl+Shift+Delete or Cmd+Shift+Delete)
```

### DNS Resolution Fails

```bash
# Check Route 53 records
aws route53 list-resource-record-sets \
  --hosted-zone-id $(cd terraform && terraform output -raw route53_zone_id)

# Verify domain nameservers point to Route 53
dig timothyolubiyi.name.ng
```

## Rollback / Cleanup

### To Delete All Resources

```bash
cd terraform/

# Check what will be destroyed
terraform plan -destroy

# Delete infrastructure (⚠️ DESTRUCTIVE)
terraform destroy

# This will delete:
# - S3 bucket and all contents
# - CloudFront distribution
# - ACM certificate
# - Route 53 records
# - IAM roles
```

### To Keep Infrastructure, Just Upload New Build

```bash
# Rebuild React app
npm run build

# Upload new version to S3
aws s3 sync dist/ s3://$(cd terraform && terraform output -raw s3_bucket_name) --delete

# Invalidate cache
aws cloudfront create-invalidation \
  --distribution-id $(cd terraform && terraform output -raw cloudfront_distribution_id) \
  --paths "/*"
```

## Security Checklist

- [ ] S3 bucket is private (no public access)
- [ ] CloudFront uses HTTPS only
- [ ] ACM certificate is valid and auto-renewing
- [ ] GitHub Actions uses OIDC (no long-lived credentials)
- [ ] Terraform state is stored locally (or in encrypted S3)
- [ ] `.tfvars` file is in `.gitignore`
- [ ] AWS credentials never committed to Git
